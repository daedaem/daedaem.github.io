# 정적 사이트 검증

## 페이지 간 일관성·접근성 보완 (2026-09-06)

이름·마크·색상 팔레트와 기존 성과 3줄은 유지했다. 성과 줄과 대표 카드에서 연결한 사례는 아래 `더 읽을 사례` 목록에서 제외해 같은 글로 반복 안내하지 않는다. 카드 전체 클릭은 유지하되 링크의 접근 가능한 이름은 제목으로 제한했다.

같은 역할의 목록 제목은 `PageHead`로, 입력·버튼·필터 칩은 공통 스타일과 크기 토큰으로 묶었다. 위키의 읽기 전용 상태 배지는 필터 버튼과 구분한다. 사례·노트·위키 본문 H2/H3는 각각 24px/19px로 구분했다. 글이 없는 카테고리는 탐색 칩에서 제외하되 기존 카테고리 URL은 유지한다. 위키 작성자 안내는 푸터로 옮겼고 상태 설명은 모바일에서도 펼쳐 볼 수 있다.

알고리즘 쪽 이동은 최소 44×44px 조작 영역을 갖는다. 번호는 처음·끝과 현재 쪽 주변의 최대 5개만 표시하고 빠진 범위는 말줄임표로 구분한다. 이전·다음과 현재 결과 범위를 두 번째 줄에 고정했다. 서버가 만든 버튼을 재사용하므로 Astro 스타일과 키보드 초점을 유지한다. 44px는 사용 편의를 위한 목표이며 전체 WCAG 인증을 뜻하지 않는다.

검증 범위:

- 11개 경로 × 4개 화면 폭(320·390·768·1440px): HTTP 200, H1 1개, 문서 가로 넘침 없음, 실행 오류 없음.
- 홈 성과 3줄과 공개 사례 링크 7개의 중복 없음, 대표·스트립 카드의 제목 기반 링크 이름.
- 위키 검색·빈 결과·초기화·주제 해시·URL 조건 복원·페이지 이동·모바일 상태 설명.
- 알고리즘 검색·유형/언어 필터·초기화·다음/마지막/중간 쪽 이동. 320·390px에서 중간 쪽 번호도 한 줄이며 버튼 크기는 44px 이상이다. 390px에서 첫 문제는 페이지 상단 기준 약 647px다.
- 사례 본문 H2/H3 크기, 모바일·데스크톱 목차와 직접 앵커 이동. Pagefind의 SCSA 검색, Escape와 검색 버튼으로의 초점 복귀.
- 홈·글 목록·위키·알고리즘의 390px/200% 글자 크기 가로 넘침 없음. JavaScript를 끈 상태의 위키 전체 목록·본문 목차.
- 라이트·다크 화면 확인. 보조 텍스트 두 색상이 각 테마의 실제 3개 배경에서 4.5:1 이상인지 회귀 테스트로 확인한다.

Node 22.23.2에서 단위 테스트 25개, Astro 검사 57개 파일(오류·경고 없음), 정적 빌드, HTML 621개와 내부 참조 21,725개 검사를 통과했다. 본문·이미지·발행 상태·기존 URL·최근 SCSA 글 변경은 건드리지 않았다. 전체 글의 사실관계나 알고리즘 풀이의 정답은 이번 UI 검증 범위가 아니다.

## 홈·탐색 개선 검증 (2026-09-05 작업)

상단 메뉴를 `글 · 위키 · 학습 기록 · 소개`로 정리했다. 새 `/learn/`은 기존 알고리즘·노트·SCSA 글로 연결하는 입구이며, 기존 URL은 그대로다. 홈 대표 사례에는 공개 본문의 판단 순서를 도식으로 요약했다. 위키의 상태·정렬 및 알고리즘 유형·언어는 필요할 때 펼친다. 사례·노트 목차는 1200px 이상에서 본문 오른쪽에, 그보다 좁은 화면에서는 접힌 형태로 나온다. JavaScript가 없어도 목차는 열린 상태로 읽을 수 있다.

검증 범위:

- 9개 경로 × 5개 화면 폭(320·390·768·1200·1440px): HTTP 200, 제목 1개, 문서 가로 넘침 없음, 브라우저 실행 오류 없음.
- 위키: 주제 해시·조건 URL 복원, 검색·상태·정렬·초기화, 빈 결과와 12개 단위 페이지 이동.
- 알고리즘: 접힌 상세 필터, 검색·언어 필터·초기화, Gold 그룹 10개 단위 페이지 이동. 390px에서 첫 문제 위치는 페이지 상단 기준 약 651px.
- 사례: 모바일 목차 펼치기, 데스크톱 옆 목차, 소제목 이동 시 고정 헤더에 가려지지 않음.
- 빌드된 Pagefind의 SCSA 검색, Escape와 검색 버튼으로의 초점 복귀. 학습 기록 보조 메뉴는 색인에서 제외하고 정적 검사로 보호한다.
- JavaScript를 끈 상태의 위키 전체 목록·목차·학습 기록 링크. 홈·위키·사례의 라이트/다크 화면 캡처 확인.

본문 파일과 공개 여부는 이 변경에 포함하지 않았다. 이 검증은 전체 글의 기술적 정확성이나 모든 알고리즘 풀이의 정답을 보증하지 않는다.

Node 22.23.2에서 단위 테스트 17개, Astro 검사 50개 파일(오류·경고 없음), 정적 빌드, HTML 621개와 내부 참조 19,354개 검사를 통과했다.

## 검사 실행 방법

현재 블로그는 읽기 중심의 Astro 정적 사이트다. 글은 Git으로 관리하고, 검색은 빌드 결과를 Pagefind로 색인한다. 이 요구에는 별도 API 서버·DB·관리자 인증을 추가하지 않는다.

Node 22에서 다음 순서로 검사한다. 배포 workflow도 같은 검사를 통과해야 산출물을 업로드한다.

```sh
npm ci
npm run check
npm test
npm run build
npm run check:site
```

`check:site`는 생성된 HTML의 주요 태그에서 따옴표로 감싼 `href`/`src`를 읽어 같은 사이트의 파일 존재 여부를 확인한다. 검색 번들·RSS·사이트맵 등 필수 산출물과 posts/wiki의 `draft: true` 문서가 생성되지 않았는지도 확인한다. 404 페이지의 canonical 경로만 예외다.

`다른 글`·`연결된 문서`·`댓글` 영역의 검색 제외 속성도 검사한다. 본문 아래 추천 목록의 제목 때문에 무관한 글이 검색되는 일을 막기 위한 규칙이다. 탐색 링크 자체는 화면에 그대로 남긴다. [Pagefind 색인 범위](https://pagefind.app/docs/indexing/) 참고.

범용 HTML 파서나 보안 감사 도구는 아니다. 외부 링크 응답, fragment 대상, `srcset`, 브라우저 동작, 기술 내용의 진위와 회사 기밀 여부는 검사하지 않는다. 초안을 숨겨도 공개 저장소의 원문·Git 이력이 비공개가 되는 것은 아니다.

UI를 바꿀 때는 빌드 후 `npm run preview`에서 아래를 직접 확인한다. 개발 서버에는 검색 색인이 없다.

- 좁은 화면의 메뉴·본문·코드·표와 가로 넘침
- 라이트/다크 테마와 키보드 초점
- 검색 결과, 닫기 버튼, Escape, 다시 열기, 닫은 후 초점 복귀
- 알고리즘·위키·노트 목록의 필터, 빈 결과, 페이지 이동
- 주요 사례 링크와 오래된 URL의 이동

읽기 화면을 수정할 때는 다음도 확인한다.

- `디스크` 검색에서 해당 사례와 실제 언급이 있는 소개 페이지는 남고, 하단의 다른 글 목록에만 단어가 있는 사례는 제외되는가
- 목차 클릭과 소제목의 직접 URL 모두 고정 헤더 아래로 이동하는가
- 블록 코드가 14px로 표시되고, 좁은 화면에서는 코드 블록 안에서 가로로 넘길 수 있는가
- 홈에서 각 사례 링크가 한 번씩 나오며, 소개·경력 버튼과 학습 위키 링크가 유지되는가

2026-09-05 읽기 UX 보완에서는 테스트 15개, 타입 검사와 빌드·내부 참조 검사를 통과했다. 격리된 Chrome에서 360·390·641·1100px 너비의 홈/본문, 목차와 직접 앵커 이동, 코드 크기, 검색 결과를 검증했다. 390·1100px 화면과 데스크톱 다크 테마 캡처도 확인했다. 본문의 사실관계나 발행 상태는 변경하지 않았다.

전역 `scroll-padding-top`과 위키 목록의 기존 `scroll-margin-top`이 중첩되지 않도록 위키도 공통 보정을 따른다. 390·1100px에서 다음/이전 페이지 이동 후 필터 위치와 결과 범위를 확인했다. 원격 검색 검증은 결과 건수만 기다리지 말고 각 결과 링크가 로드될 때까지 기다린다.

2026-09-05 검사에서는 단위 테스트 5개, Astro 타입 검사, 정적 빌드와 내부 참조 검사를 통과했다. 브라우저로 모바일 홈·본문, SCSA 검색, 검색 닫기·재열기·Escape·초점 복귀, 알고리즘 페이지 이동·빈 결과를 확인했다. 전체 접근성 인증이나 모든 글의 기술 검증을 의미하지는 않는다.
