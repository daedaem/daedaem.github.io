## 검사 실행 방법

현재 블로그는 읽기 중심의 Astro 정적 사이트다. 글은 Git으로 관리하고, 검색은 빌드 결과를 Pagefind로 색인한다. 이 요구에는 별도 API 서버·DB·관리자 인증을 추가하지 않는다.

Node 22에서 다음 순서로 검사한다. 배포 workflow도 같은 검사를 통과해야 산출물을 업로드한다.

```sh
npm ci
npm run check
npm test
npm run build
npm run check:site
```

`check:site`는 생성된 HTML의 주요 태그에서 따옴표로 감싼 `href`/`src`를 읽어 같은 사이트의 파일 존재 여부를 확인한다. 검색 번들·RSS·사이트맵 등 필수 산출물과 posts/wiki의 `draft: true` 문서가 생성되지 않았는지도 확인한다. 404 페이지의 canonical 경로만 예외다.

`다른 글`·`연결된 문서`·`댓글` 영역의 검색 제외 속성도 검사한다. 본문 아래 추천 목록의 제목 때문에 무관한 글이 검색되는 일을 막기 위한 규칙이다. 탐색 링크 자체는 화면에 그대로 남긴다. [Pagefind 색인 범위](https://pagefind.app/docs/indexing/) 참고.

범용 HTML 파서나 보안 감사 도구는 아니다. 외부 링크 응답, fragment 대상, `srcset`, 브라우저 동작, 기술 내용의 진위와 회사 기밀 여부는 검사하지 않는다. 초안을 숨겨도 공개 저장소의 원문·Git 이력이 비공개가 되는 것은 아니다.

UI를 바꿀 때는 빌드 후 `npm run preview`에서 아래를 직접 확인한다. 개발 서버에는 검색 색인이 없다.

- 좁은 화면의 메뉴·본문·코드·표와 가로 넘침
- 라이트/다크 테마와 키보드 초점
- 검색 결과, 닫기 버튼, Escape, 다시 열기, 닫은 후 초점 복귀
- 알고리즘·위키·노트 목록의 필터, 빈 결과, 페이지 이동
- 주요 사례 링크와 오래된 URL의 이동

읽기 화면을 수정할 때는 다음도 확인한다.

- `디스크` 검색에서 해당 사례와 실제 언급이 있는 소개 페이지는 남고, 하단의 다른 글 목록에만 단어가 있는 사례는 제외되는가
- 목차 클릭과 소제목의 직접 URL 모두 고정 헤더 아래로 이동하는가
- 블록 코드가 14px로 표시되고, 좁은 화면에서는 코드 블록 안에서 가로로 넘길 수 있는가
- 홈에서 각 사례 링크가 한 번씩 나오며, 소개·경력 버튼과 학습 위키 링크가 유지되는가
