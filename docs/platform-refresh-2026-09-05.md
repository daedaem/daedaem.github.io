# 블로그와 학습 위키 정비

## 결정

- 기존 GitHub Pages 주소와 모든 글 슬러그를 유지한다. 서버·DB 재구축 대신 읽기와 편집을 분리한다.
- Astro 5.18.2에서 7.3.1로 올린다. MDX 8, Markdown remark 7.3을 함께 사용한다. 아카이브 보정 플러그인을 유지하기 위해 `unified()`를 명시하고, 기존 공백 처리도 보존한다.
- Node 22.12 이상이 필요하다. 검증 환경은 Node 22.23.2다. TypeScript는 기존 검사 도구와 검증된 5.9.3을 유지하며, 최신이라는 이유만으로 7로 올리지 않는다.
- 글의 저장 위치는 Markdown 파일이다. 웹 편집은 Pages CMS의 무료 호스팅 서비스를 사용하도록 구성한다. 자체 CMS를 호스팅하면 생기는 인증·DB 관리 책임은 추가하지 않는다.

## 화면

홈에서 사례와 학습 위키로 바로 갈 수 있다. 대표 증거는 세 개로 줄여 소개가 모바일에서 과도하게 길어지는 문제를 완화한다. 나머지 사례는 기존 목록에 그대로 있다.

위키는 최근 갱신순·제목순, 주제·정리 상태, 제목·설명·태그 검색을 조합한다. 한 번에 12개 문서를 표시하고 조건은 URL에 남긴다. 기존 `/wiki/#database` 같은 링크도 주제 선택으로 유지한다. JavaScript가 없으면 전체 문서를 볼 수 있다. 문서 하단에는 자신을 참고한 문서와 태그가 겹치는 문서를 구분해서 연결한다.

## 편집과 공개 범위

`/admin/`은 noindex 안내·편집 진입 페이지이지 자체 로그인이나 권한 장벽이 아니다. 실제 편집기는 Pages CMS다. 사용자가 로그인하고 GitHub App에 이 저장소 접근을 승인해야 한다. 이 승인 이전에 작성·저장·삭제의 실제 왕복 검증을 완료했다고 표현하지 않는다.

CMS 설정에는 posts/wiki와 원문 편집용 notes만 노출한다. 미발행 기본값, 이미지 업로드 위치, 분류·상태를 지정한다. 파일명 변경은 막아 URL을 보존한다. GitHub App의 저장소 접근 권한이 이 폴더로만 제한되는 것은 아니다. UI 범위와 보안 권한을 혼동하지 않는다.

공개 저장소의 초안·이미지는 누구나 원문을 볼 수 있다. 삭제는 Git 이력 삭제가 아니다. 비공개 업무 정보는 이 공간으로 이전하지 않는다. 노션에서 가져오는 주제도 개인 구현 경력으로 재포장하지 않는다.

## 검증과 한계

자동 검사에는 타입·빌드·필수 파일·내부 참조·초안 제외와 CMS 필드 정합성, 1,000문서의 검색·페이지 경계 테스트를 포함한다. 이는 회사 기밀 판정, CMS 로그인 완료, 모든 글의 사실 검증이나 1,000개 문서의 실제 브라우저 성능 측정을 뜻하지 않는다.

관리자 페이지는 사이트맵과 Pagefind 검색에서 제외한다. CMS의 잘못된 편집으로 빌드가 실패하면 배포 단계에 가지 않는다. 저장된 GitHub 원문 자체는 이미 공개되므로 배포 검사로 기밀 노출을 막을 수 있다고 설명하면 안 된다.

## 검수 보완

최종 로컬 검증: 타입 검사 오류·경고 0건, 단위 테스트 13개 통과, HTML 620개와 내부 참조 18,948개 검사 통과, Pagefind 555페이지 색인. enum 예제는 JDK 21에서 `javac --release 17`로 컴파일하고 금지 전이 차단 출력을 확인했다. 실제 SQL Server 인스턴스에서 새 DB 예제를 실행한 것은 아니다.

Claude의 읽기 전용 코드 리뷰 뒤 기존 위키의 공개 상태를 명시적으로 보존하고, CMS 새 파일 기본 이름을 ASCII 날짜·시간으로 바꿨다. 사용자는 생성 시 설명형 영문 파일명으로 바꿀 수 있다. URL 갱신은 250ms 지연하고 예외가 필터를 중단시키지 않게 했다. 모바일 첫 화면과 SCSA 검색, 위키 페이지 전환을 실제 빌드 미리보기에서 확인했다.

CMS select의 `name` 키, filename 객체, fields 생략 시 raw 편집은 현재 공식 문서가 지원하는 규격이므로 추측성 수정 제안은 적용하지 않았다. 실제 로그인·편집 왕복은 사용자 연결 뒤에만 확인할 수 있다.
