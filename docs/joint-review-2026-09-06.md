## 검토 방식과 범위

Claude 앱의 Fable 5.1과 Codex가 공개 소스 `9e197e2`를 각각 검토했다. Claude의 첫 보고서에 Codex의 재현 결과·반론·수정안을 전달하고, 동의와 이견을 확인한 뒤 아래 범위를 정했다. 비공개 Notion·이력서·회사 자료는 검토 자료로 전달하지 않았다.

- 사례 7편: 양쪽이 본문을 읽었다. 공개 내용에 없는 경력 사실은 추가하지 않았다.

- 노트 26편: 양쪽이 날짜·정정 기록을 대조했다. 이번 본문 검수는 선택 검토이며 전수 기술 검증이 아니다.
- 알고리즘 494편: 생성 페이지·구조 검사와 기존 실행 예제 테스트를 구분한다. 외부 채점기 재채점은 하지 않았다. `boj-1620`·`pg-42883`의 기존 확인 필요 안내를 유지한다.

## 반영한 것

### 작성일·수정일·사례 시점 구분

사례의 `date`, 원래 노트를 쓴 `date`, 위키의 `created` 값은 바꾸지 않았다. 사례 발생 시점인 `happened`를 작성일과 분리해 “사례 시점”으로 표시한다. 작성·수정은 공통 `ContentDates`를 사용하고, 아카이브에는 “원문 작성”을 붙였다. 사례 목록·홈·카테고리·태그에도 날짜의 의미를 표시한다. 정렬 기준은 유지한다.

노트 19편은 2026년 교정·보충 문장이 있는데 수정일이 2023년이거나 없었다. 이번에 제목·구조를 고친 SCSA·시멘틱 태그는 실제 수정일을, 나머지 17편은 본문에 명시된 가장 최근 보충 날짜를 반영했다. 파일 이동 시각이나 빌드 시각을 작성일로 쓰지 않는다. 본문 내부의 수평선 이후에 있는 교정도 검사하도록 회귀 테스트를 추가했다.

### SCSA와 중복 제목

제목은 “삼성전자 SCSA 합격, 최종 입사는 하지 못했다”로 정했다. 횟수를 앞세우지 않으면서 최종 미입사 사실을 명시하고, 이유는 요약과 원래 본문에 남겼다. “불발”보다 결과가 명확하고, 실패 이유 전체를 제목에 반복하는 안보다 짧다는 판단이다.

SCSA와 시멘틱 태그 노트의 중복 본문 제목을 제거하되 기존 fragment용 빈 앵커는 남겼다. 감상·판단·기존 슬러그·리다이렉트와 사용자가 공개 유지로 결정한 이미지는 보존한다. 승인된 이미지 유지는 검토 누락이 아니라 기존 사용자 결정을 따른 것이다.

### 조작 영역과 댓글 로딩

모바일 검색·테마 버튼을 34px에서 공통 44px 조작 영역으로 확대했다. 편의를 위한 목표이며 전체 WCAG 인증을 의미하지 않는다.

글 진입 직후 테마를 바꾸면 지연 로딩된 댓글만 이전 테마로 남는 경합을 고쳤다. 클라이언트 생성 전 속성을 갱신하고, iframe 로드·준비 통지 뒤 현재 테마를 다시 전한다. 메시지의 origin·source를 확인하고 반복 크기 통지에 전송이 순환하지 않도록 한다. 외부 CSS 로딩 전에도 iframe이 좁은 본문을 밀어내지 않도록 너비를 지정한다. [giscus 메시지 API](https://github.com/giscus/giscus/blob/main/ADVANCED-USAGE.md), [공식 클라이언트](https://github.com/giscus/giscus/blob/main/client.ts).

### 내용의 기술적 정확성

- 인증 글: 하드웨어·설정 근거 없는 성능 배율을 삭제하고 작업 비용과 실제 부하에 따라 판단하도록 고쳤다. 다른 추정 배율로 바꾸지 않았다. [OWASP 비밀번호 저장 지침](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html#using-work-factors).
- React Context 위키: 값 전달과 상태 변경 로직의 역할을 구분하고, `useReducer`와의 상태 관리 조합을 설명했다. 갱신 빈도만으로 부적합하다고 단정하지 않고 값의 비교·구독 범위·렌더링 비용을 보도록 고쳤다. [React reducer와 Context](https://react.dev/learn/scaling-up-with-reducer-and-context), [useContext](https://react.dev/reference/react/useContext).
- 네트워크 위키: 일반적인 능동 종료 예제에서 TIME_WAIT의 주체와 목적을 도식·설명에 일치시켰다. 경로 학습과 전달 테이블 기반 다음 홉 선택도 구분했다. [RFC 9293 §3.6](https://www.rfc-editor.org/rfc/rfc9293.html#section-3.6), [RFC 1812 §5.2.4](https://datatracker.ietf.org/doc/html/rfc1812#section-5.2.4).

### 큰 사진의 전송 크기

`first-post`만 MDX로 옮겨 Astro Image로 파생 크기와 srcset을 제공한다. 원본 파일과 URL은 유지한다. 두 사진의 가장 큰 파생 후보 합계는 398,690바이트이고, 실제 선택은 화면 크기·픽셀 밀도에 따라 달라진다. 704px 기본 파일 두 장의 합계는 138,060바이트다. 다른 사진·도해에 일괄 축소를 적용하지 않았다. [Astro Image widths](https://docs.astro.build/en/reference/modules/astro-assets/#widths).

## 유지하기로 합의한 것

- RSS는 사례 발행과 위키 갱신을 함께 알리는 기존 동작을 유지한다. 위키 `created`가 블로그 최초 공개일인지 검증되지 않아 그 값으로 `pubDate`를 일괄 교체하는 제안은 철회했다. 대신 위키 항목 설명에 최초 작성·최근 갱신 날짜의 의미를 표시한다.
- 홈 성과 3줄, 이름·마크·팔레트, 공개 사례 7편, 프로젝트 노출 범위, 정적 배포 구조는 유지한다.
- 실제 구현하지 않은 경험이나 공개 자료로 증명되지 않는 경력·성과는 덧붙이지 않는다.
