# s4 파랑 단면도 디자인 운영 이식

2026-09-29. 승인된 `s4-iso-blue-refined` 시안을 운영에 옮겼다. 기준은 기존 운영 `daec306`이며, 예전 로컬 checkout이나 목업의 본문으로 콘텐츠를 덮지 않았다.

## 바뀐 화면

- 홈은 최신순 한 열 목록이다. s4의 제목·요약·분류·날짜와 데스크톱 220×160px 표지, 모바일 제목→176px 표지→요약→메타 순서를 적용했다.
- 공통 머리줄은 64px의 글·위키·소개 메뉴다. 검색과 테마 버튼은 실제 기능을 유지하며 학습 기록과 프로젝트는 바닥글 및 기존 문서 경로에서 접근한다.
- 글 목록·분류·태그의 사례에는 같은 표지를 쓴다. 위키·과거 노트의 목록 부품은 분리해 유지했다.
- 사례 본문은 최대 680px와 우측 표지·고정 목차다. 모바일은 접힌 native 목차이며 선택하면 접고 제목으로 초점을 옮긴다. 과거 노트의 기존 목차 시트는 유지한다.
- 소개는 s4 프로필·그림·본문·고정 목차로 바꿨다. 본문 문장과 사례 데이터, AI 편집·개념 표지 안내는 유지한다. 이력서 파일이나 다운로드 버튼을 추가하지 않았다.
- s4 SVG 7장을 그대로 사용한다. 기존 표지 원본도 삭제하지 않는다.

## 보존 확인

- `src/content/`의 591개 파일은 작업 시작 전과 SHA-256이 동일하다. 발행 상태·날짜·글 본문·요약을 수정하지 않았다.
- `src/data/cases.ts`, 프로젝트 데이터, 사이트 정보는 불변이다. 소개의 기존 문단·제목·정의 42개가 모두 보존됐다.
- 지원서나 개인 이력서 파일을 공개 저장소·배포물에 넣지 않았다. 기존 공개 자산에도 PDF 파일이 없었다.
- 554개 문서의 Pagefind 전체 검색, RSS·sitemap·OG·기존 URL, 관련 기록·위키, 코드·표 조작 및 댓글 로딩을 유지한다.

## 검수

- 320·390·768·1280·1440px, 라이트·다크: 홈·목록·분류·위키·노트·알고리즘·프로젝트 등 80조건에서 페이지 가로 넘침·중복 ID·이력서 링크가 없었다.
- 소개와 정수 사례를 320·390·1280px 두 테마로 캡처했고 별도 검토자가 직접 확인했다. 사례 6편의 320px 고지·넘침도 확인했다.
- 목차 선택·현재 절·접힘·초점, 데스크톱 고정 위치, 코드 키보드 가로 스크롤을 확인했다. 실제 검색에서 BigDecimal 2건과 본문 이동, 클릭으로 연 검색의 Escape 초점 복귀를 확인했다.
- 독립 검토에서 찾은 목록 제목 단계(h1→h3)와 로고 이름 불일치를 수정했다. 홈의 행은 h3, 독립 목록은 h2이며 브랜드 접근성 이름에 보이는 작성자 이름을 포함한다.
- 최종 axe: 홈·목록·본문·소개 ×320/1280×라이트/다크 16조건, WCAG 2/2.1 A·AA 자동 규칙 위반0. 수동 판정 항목을 포함한 인증은 아니다.
- 최종 로컬 Lighthouse 모바일: 홈 성능99·접근성100·권장사항100·SEO100, 정수 본문98/100/100/100. 둘 다 CLS0. 공개 네트워크나 실제 휴대폰 성능을 보장하는 수치가 아니다.
- 정적 빌드: 618 HTML, 내부 참조21,162건 검사 통과. 타입 오류0·경고0, 기존 힌트2.

## 한계

실제 휴대폰·Safari·스크린리더 및 독자 조사는 수행하지 않았다. 외부 유명 디자이너가 참여했다는 의미가 아니며, 자동 검사 통과를 디자인 품질이나 채용 결과의 보장으로 표현하지 않는다.
