# 읽기 구조 A/B 재검토 — 2026-09-11

## 범위와 판단 기준

기준 A는 `835b8ed`, 최초 B는 `640ba12`, 보완 B는 `50e3caf`다. 사용자는 A/B 비교 뒤 더 나은 변경만 반영하고, 그렇지 않은 변경은 기각하도록 승인했다. 이전 비교 기록의 '선택 대기'는 그 시점의 상태다.

기술 블로그에서 글을 고르고 읽는 작업을 우선하되, 대표 표지와 제목·부제의 시각적 위계를 잃지 않는지 함께 본다. 합격률이나 UX 점수를 측정하는 실험은 아니다.

## 보완 후보에서 채택·기각한 것

- B의 홈 읽기 목록과 주제 레일, 공통 글 목록/카테고리 구조를 채택했다.
- 모든 표지를 같은 작은 썸네일로 만드는 것은 기각했다. 첫 홈 표지는 해당 글 열의 40%, 나머지는 기존 88/144px로 보존한다. 이미지 원본·3:2 비율·로딩 우선순위는 그대로다.
- 상세 제목·부제를 한 줄 스타일로 합치는 것은 기각했다. 부제는 별도 줄로 유지하며 H1은 28–44px, 사례 본문은 17px/1.9로 둔다.
- 원인 요약의 채운 상자를 세로선으로 정리하고 데스크톱 목차를 제목 옆까지 올렸다.
- 모바일 주제 메뉴는 '주제 고르기 / 현재: …'로 명확히 했다. 기본 HTML은 닫힌 native details이고 바로 뒤의 동기 inline 스크립트가 데스크톱만 연다. 초기화 전에는 summary를 숨기지 않아 JS가 없어도 열 수 있는 구조다.
- 모바일 nav를 CSS로 강제 숨기고 JS로만 여는 제안은 native 상태와의 불일치 및 JS 실패 시 탐색 상실 때문에 기각했다. 중간 페인트가 절대 없다는 주장은 하지 않는다.
- 가로 스크롤 주제, 행 내부 분류 링크 추가, 미비교 위키 본문 크기 변경, 프레임워크·호스팅 교체는 이번에 적용하지 않는다.

500px 전체 폭 대표 카드와 모바일 240px 상단 표지는 구현·측정하지 않았다. 채택 후보는 목록 안에서 대표 표지를 더 크게 두는 형태이며, 원래 A의 대형 편집 지면을 복원했다고 표현하지 않는다.

## Codex 직접 비교

같은 Mac 브라우저에서 두 정적 빌드를 비교했다. 모바일은 390×844, 데스크톱은 1440×900이며 스크롤바로 client width가 15px 작다. 실제 휴대폰 측정이 아니다. y는 페이지 최상단에서 글자 박스까지의 CSS px다.

| 항목 | A 모바일 | 보완 B 모바일 | A 데스크톱 | 보완 B 데스크톱 |
| --- | ---: | ---: | ---: | ---: |
| 홈 첫 제목 y | 536 | 385 | 255 | 346 |
| 홈 첫 화면에 완전히 보이는 추천 제목 | 1 | 2 | 1 | 3 |
| 글 목록 첫 제목 y | 579 | 395 | 400 | 342 |
| 글 목록 첫 화면의 완전한 제목 | 1 | 2 | 2 | 3 |
| NULL 글 본문 시작 y | 810 | 767 | 621 | 561 |
| 사례 본문 글자/행간 | 16/28.8 | 17/32.3 | 16/28.8 | 17/32.3 |

보완 B 모바일 홈의 세 번째 제목은 y844부터 시작하므로 첫 화면에 완전히 보이지 않는다. 데스크톱 첫 제목 도달은 A가 91px 더 빠르다. B가 모든 지표에서 이긴다는 주장은 틀리다. 대신 선택할 수 있는 글 수, 목록 진입, 본문 읽기 간격이 개선된다. 표지는 A보다 작아 시각적 무게가 줄고, 모바일 주제를 보려면 한 번 펼쳐야 하며, 큰 본문은 문서 전체를 길게 만든다.

## 검증

- Codex: 테스트 112개 통과, skip 0. 타입 검사 89파일 오류/경고/힌트 0. Astro 593페이지, check:site 621 HTML / 21,782 내부 참조 통과.
- A/B 양쪽 홈·목록·NULL 상세를 390/1440에서 캡처·측정했다. B는 추가 320/375/768 세 화면에서 가로 넘침 0, 320 다크 세 화면을 직접 확인했다.
- 모바일 주제 summary 44px, Enter 열기와 여섯 탐색 링크 높이 44px, 카테고리 이동 및 현재 주제 표시를 확인했다.
- 검색 SCSA 2건, Escape 후 검색 버튼 초점 복귀, 목차 Oracle 항목 이동/현재 위치 표시를 확인했다. 목차 이동 후 제목 y112는 헤더 하단 y81보다 아래다.
- 콘텐츠 592개를 포함한 보호 파일 737개가 기준 A와 바이트 동일하다. 621 HTML 경로 및 804 코드 블록도 동일하다.
- 글 본문·날짜·발행·URL·브랜드·팔레트·표지 원본·OG·위키·학습 기록·의존성·배포 구성은 변경하지 않는다. 비공개 Notion/이력서에 접근하거나 전송하지 않았다.

공개 사례 7편 모두 320px에서 가로 넘침 0, 사례 본문 17px, 부제가 있는 글은 별도 줄인 것을 추가 확인했다. 홈 사례 링크 7개는 중복이 없다. 실제 스크린리더·실기기·독자 조사·새 Lighthouse/PSI·CMS/댓글 쓰기·전체 본문 감사는 Codex가 이번에 수행하지 않았다.

## Claude 독립 검토와 최종 결정

Claude 앱의 기존 블로그 검토 대화(Fable 5.1, Extra)에 공개 코드만 전달해 설계 반론과 구현 재검토를 진행했다. Claude는 정확한 `50e3caf`와 A를 별도 scratchpad에서 빌드하고 같은 Chromium의 375/390/1440 라이트·다크로 홈·목록·NULL 상세를 비교했다고 보고했다.

- Claude 테스트는 111/112이며 실패 1건은 이전에도 있었던 그 컨테이너의 C++ ASan 부재다. Codex의 112/112 결과와 구분한다.
- Claude는 check:site, 콘텐츠/public diff 없음, 세 화면 Lighthouse 접근성 100을 직접 확인했다고 보고했다. 이는 UX 100점, 실제 스크린리더 검증, 새 성능 점수라는 뜻이 아니다.
- JS 비활성화 상태에서 summary로 주제를 열 수 있음, 키보드 Tab→summary→Enter→전체 글 링크 진입을 확인했다고 보고했다. 데스크톱 첫 페인트의 순간 상태는 측정하지 않았다.
- 첫 제목 위치와 완전 노출 개수는 Codex 측정과 몇 px 이내로 부합한다. 모바일 390 환경의 표지 폭 차이(140 대 134)는 client width/스크롤바 차이다.
- Claude는 홈·글 목록·글 상세 모두 보완 B 채택과 배포에 동의했다. Codex도 독립 측정과 시각 확인을 바탕으로 동의했다.

최종 채택은 `50e3caf`의 보완 B다. 시각적 개성에는 A의 대형 표지가 더 강하지만, 기술 블로그의 글 선택·주제 탐색·본문 읽기 이득이 손실보다 크다고 판단했다. 대표 표지 40%는 큰 썸네일이며 hero가 아니다. 대표 표지를 추가로 50%까지 늘리거나 byline을 압축하는 후속 제안은 미측정이므로 이번 반영에서는 기각한다.

콘텐츠·발행 정책이나 호스팅을 바꾼 전면 재구축이 아니라, 실제 A/B 비교에서 채택한 읽기 구조 변경이다. 검증 문서 외 추가 소스 변경 없이 이 커밋을 운영에 반영한다.
