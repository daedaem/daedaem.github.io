# 2026-09-05 재검수

기존 검수 완료 판단과 별개로 코드·콘텐츠·브라우저를 다시 확인했다. 이 문서는 검수 범위 기록이며 모든 콘텐츠의 정확성을 보증하는 인증서가 아니다.

## 수정

- 알고리즘 목록: `display: grid/flex`가 `hidden`을 덮어써 페이지 밖의 행이 계속 보이던 오류 수정. Gold 128개가 한 번에 보이던 것을 페이지당 10개로 복구했다.
- 검색: 작업 시작 전 남아 있던 재시도·로딩·다크 테마 변경은 원문 그대로 별도 커밋 `6954704`로 보존했다.
- 주소 조회 사례: DB 조회 9초→1초대와 외부 API 응답 100ms대를 홈·소개에서도 구분했다. OOM 직접 원인은 추정으로 한정하고 대체 조회 경로는 구현 성과가 아닌 추가 설계안으로 표시했다.
- 금액 사례: Java 정수 오버플로와 JDBC 변환을 구분했다. 정확한 발생 지점 미확정을 요약에도 반영했고 `long`과 `BigDecimal`의 선택 조건을 정리했다.
- 디스크 사례: 내부 미할당 공간과 실제 행 크기의 차이, 여유 공간 조회 누락 조건, smallfile/bigfile 차이, OS 여유와 DB 내부 여유를 구분했다.
- 위키: 트랜잭션 rollback-only 예외, 정규화 정의, JOIN의 행 조합과 중복 보존, NOT IN의 FALSE/UNKNOWN, 트리거 실행 조건, React 초기화·의존성·상태, 세션 유지 조건, HTTP 연결과 렌더링 등의 단정을 보완했다.
- 학습 노트: TypeScript 출력 설정·파일 포함 규칙·readonly·정적 멤버, 클로저·프로토타입·완료 값의 오류를 취소선과 날짜가 있는 정정으로 남겼다. 슬러그와 당시의 감상은 유지했다.
- 두 사례는 검수 기준을 충족할 때까지 `draft: true`로 보류하고 직접 링크를 제거했다. 비공개 업무 세부사항은 이 문서에 재기재하지 않는다.

## 검증

- Node 22.23.2: `npm run check` 통과(38개 파일, 오류·경고·힌트 0).
- `npm run build` 통과, Pagefind 550페이지 색인 생성.
- 로컬 브라우저: Gold 10행 표시, 다음 페이지 11–20/128, 결과 없음, 필터 초기화 1–10/128 확인.
- 검색: SCSA 결과에서 해당 노트와 소개 확인. 모바일 다크 모드에서 Oracle 검색 확인.

- 댓글: giscus의 댓글 0개·입력 영역·GitHub 로그인 UI 확인. 실제 댓글 제출이나 로그인은 하지 않음. 새 글에서 Discussion not found 메시지는 첫 댓글 전 상태이며 작성 성공 검증을 대신하지 않음.

- 임시 비공개 두 글의 HTML이 생성되지 않음 확인. 사이트맵·RSS·OG의 초안 제외도 점검 대상이다.
- NULL 비교 예제: Java 21에서 null·빈 문자열·공백·일반 문자열 등의 49쌍을 실행해 수정 전후 판정이 모두 같음을 확인. 이 테스트는 업무 시스템 재현이 아니며, 본문 예제가 해결을 설명하지 못한다는 근거다.

## 범위와 남은 확인

- 사례 글 6편, 위키 24편, 학습 노트 26편을 대상으로 서술 중심 검수를 진행했다. 모든 코드 블록을 실행한 것은 아니며 전체 내용 무오류를 선언하지 않는다. 긴 노트의 모든 코드·역사적 주장과 외부 링크는 추가 검수가 필요하다.
- SCSA 글은 공채 합격과 최종 입사 불발을 구분하고 있다. 당시 감상은 임의로 성공 서사로 바꾸지 않았다.
- 알고리즘 494편은 페이지 생성·탐색 대상으로 검사했다. 풀이 정답성·복잡도 전체 재검증이나 온라인 저지 재제출은 하지 않았다.
- 실제 경험 확인이 필요한 사례는 실패 입력, 수정 조건, 구현·배포 여부를 작성자에게 확인한 뒤 공개한다. 카테고리를 채우려고 사실 미확인 글을 복구하지 않는다.
- `draft`는 생성 사이트의 노출을 막을 뿐 공개 저장소의 원본·Git 이력·검색엔진 캐시를 지우지 않는다. 이력 삭제나 검색엔진 삭제 신청은 수행하지 않았다.
- 이번 검수는 블로그 범위이며 로컬 이력서 HTML 전체 재검수는 포함하지 않았다.
