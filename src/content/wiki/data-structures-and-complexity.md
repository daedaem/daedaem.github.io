## 복잡도

**시간 복잡도**는 입력 크기에 대해 알고리즘이 실행되는 데 걸리는 시간이고, **공간 복잡도**는 필요한 메모리 양이다.

### 빅오 표기법

**복잡도에 가장 큰 영향을 주는 항만 남기고 상수 인자를 지운다.**

```
n² + 2n   ⇒  O(n²)
2n⁴ + 3n  ⇒  O(n⁴)
```

```java
for (int i = 0; i < n; i++)
    for (int k = 0; k < n; k++)
        for (int c = 0; c < 1000; c++) { }
// O(n²) — 가장 안쪽은 1000으로 고정이라 상수다
```

```java
for (int j = 1; j < n; j *= 2) { }
// O(log n) — 매번 두 배씩 건너뛴다
```

공간 복잡도는 이렇게 센다. `int numbers[1000]` → 4바이트 × 1000 = 4,000바이트.

## 선형 구조

| | 임의 접근 | 삽입·삭제 | 탐색 |
|---|---|---|---|
| **배열** | **O(1)** | O(n) | O(n) |
| **연결 리스트** | 불가 | **O(1)** | O(n) |
| **스택** | — | O(1) | O(n) |
| **큐** | — | O(1) | O(n) |

**배열**은 같은 타입의 값을 인접한 메모리에 모아둔다. 크기가 정해져 있고, 인덱스로 바로 접근할 수 있어 O(1)이다. 대신 중간에 넣거나 빼면 뒤를 전부 밀어야 해서 O(n)이다.

**연결 리스트**는 노드를 포인터로 잇는다. 삽입·삭제는 해당 노드의 참조를 이미 갖고 있으면 포인터만 바꾸면 되어 O(1)인데, **인덱스로 바로 갈 수 없어** 탐색이 O(n)이고, 위치를 찾는 것까지 포함하면 삽입·삭제도 O(n)이다. 종류는 셋이다 — 싱글(next만), 더블(next+prev), 원형(마지막이 헤드를 가리킴).

> 배열과 연결 리스트는 **접근 속도와 변경 속도를 맞바꾼 것**이다. 어느 쪽이 잦은지로 고른다.

**스택**은 후입선출(LIFO). 재귀 함수, DFS, 되돌리기 기능에 쓴다.
**큐**는 선입선출(FIFO). CPU 작업 대기열, 캐시, BFS에 쓴다.

## 그래프

**정점(vertex)** 과 **간선(edge)** 으로 이루어진다.

- 방향이 없으면 **무방향 그래프**, 있으면 **방향 그래프**
- **Degree** — 정점에 연결된 간선 수. 방향 그래프에서는 나가는 것(Outdegree)과 들어오는 것(Indegree)으로 나뉜다
- 간선에 비용이 붙으면 **가중치 그래프**
- 구현은 **인접 행렬** 또는 **인접 리스트**

인접 리스트에서 전체 그래프를 탐색하는 **DFS**(깊이 우선)와 **BFS**(너비 우선)는 **O(V+E)** 다. 인접 행렬에서 매 정점의 이웃을 모두 검사하면 **O(V²)** 이다.

## 트리

부모-자식의 계층 관계를 표현한다. **사이클이 없는 연결된 무방향 그래프**다. 연결 조건이 빠지면 트리가 아니라 숲(forest)이다.

| 용어 | 뜻 |
|---|---|
| 루트 노드 | 최상위 노드 |
| 단말(리프) 노드 | 자식이 없는 노드 |
| 내부 노드 | 리프를 제외한 모든 노드 |
| 높이 | 루트에서 리프까지 거리 중 가장 긴 것 |
| 레벨 | 루트에서 특정 노드까지의 최단 거리 |
| 형제 | 같은 부모를 가진 노드 |

### 이진 트리의 종류

자식이 둘 이하인 트리다.

- **정이진**(full) — 자식이 0개 또는 2개
- **완전 이진**(complete) — 마지막 레벨 빼고 꽉 차 있고, 마지막은 **왼쪽부터** 채워짐
- **변질**(degenerate) — 자식이 하나뿐. 사실상 연결 리스트
- **포화**(perfect) — 모든 노드가 꽉 참
- **균형**(balanced) — 높이가 O(log n)이 되도록 균형을 관리하는 트리. 모든 노드에서 좌우 높이 차를 1 이하로 제한하는 것은 AVL 트리의 규칙이다

### 이진 탐색 트리(BST)와 그 문제

오른쪽 서브트리에는 큰 값, 왼쪽에는 작은 값이 들어간다. 보통 **O(log n)** 인데 **최악에는 O(n)** 이다. 정렬된 데이터를 순서대로 넣으면 한쪽으로 쏠려 변질 트리가 되기 때문이다.

**AVL 트리**가 이걸 푼다. 두 서브트리 높이 차를 항상 1 이하로 유지하고, 삽입·삭제 때마다 회전으로 균형을 잡는다. 탐색·삽입·삭제 모두 **O(log n)** 을 보장한다.

**레드블랙 트리**도 같은 목적이다. 핵심 규칙은 다음과 같다.

- 각 노드는 빨간색 또는 검은색이고, 비어 있는 리프(`NIL`)는 검은색으로 본다
- 빨간 노드의 자식은 반드시 검은색
- 어떤 노드에서 각 `NIL` 리프까지 가는 모든 경로에는 같은 수의 검은 노드가 있다

이 규칙 때문에 루트에서 가장 먼 리프까지의 거리가 가장 가까운 리프까지 거리의 두 배를 넘지 않는다. 따라서 탐색·삽입·삭제가 O(log n)이다. C++ 표준은 구현 자료구조를 강제하지 않지만, 주요 표준 라이브러리의 `set`과 `map`은 보통 레드블랙 트리로 구현한다.

### 힙

이진 트리 기반이다. **최소 힙**은 루트가 최솟값, **최대 힙**은 루트가 최댓값이고, 이 관계가 모든 노드-자식 쌍에서 성립한다. 우선순위 큐의 구현체다.

## 맵 · 셋 · 해시 테이블

**맵**은 key-value 조합, **셋**은 중복 없는 고유 요소의 집합이다.

C++ STL에서 `map`/`set`은 **균형 이진 트리(레드블랙)**, `unordered_map`/`unordered_set`은 **해시** 방식이다. 전자는 정렬 순서가 유지되고 O(log n), 후자는 순서가 없고 평균 O(1)이다.

**해시 테이블**은 해시 함수로 변환한 값을 인덱스로 삼아 key와 value를 저장한다. 검색·삽입·삭제가 **평균 O(1)** 이다. 다만 해시 충돌이 몰리면 최악에는 O(n)까지 떨어진다.
