## 데이터와 정보

- **데이터** — 수집했지만 아직 특정 목적으로 정제하지 않은 값
- **정보** — 데이터를 목적에 맞게 분석·가공해 의미를 부여한 결과

데이터가 원석이면 정보는 보석이다. 카드 결제 내역 자체는 데이터지만, "커피 전문점 결제 최상위가 30~40대 남성"은 정보다.

가치 있는 정보를 얻으려면 데이터를 **효율적으로 관리**해야 하고, 그 조건은 넷이다.

- 통합해서 관리한다
- 일관된 방법으로 관리한다
- 누락과 중복을 없앤다
- 여러 사용자가 동시에 실시간으로 쓸 수 있다

## 파일 시스템은 왜 부족했나

데이터베이스 개념이 나오기 전에는 응용 프로그램마다 자기 파일에 데이터를 저장했다. 디렉터리와 파일의 계층 구조를 쓰는 방식이라 **각 파일의 데이터가 서로 연관이 없다.**

학사 프로그램과 장학금 신청 프로그램이 각각 학생의 재학 상태를 들고 있다고 하자.

| 학사 프로그램 | 장학금 신청 프로그램 |
|---|---|
| 학번, 이름, 학과, 학년, **상태** | 신청 종류, 신청 일자, 학번, **재학 상태**, 신청 가능 여부 |

같은 학생이 학사 쪽에는 **졸업**으로 등록됐는데 장학금 쪽에 그게 반영되지 않으면, **졸업생이 장학금을 신청할 수 있게 된다.** 재학 상태라는 하나의 사실이 두 곳에 흩어져 있기 때문에 생기는 일이다.

여기서 나오는 결론이 데이터베이스다. **여러 응용 프로그램이 쓸 데이터를 한곳에서 관리하고 함께 쓴다.**

## DBMS가 해결한 것

DBMS(DataBase Management System)는 데이터 조작과 관리를 전담하는 시스템 소프트웨어다. 응용 프로그램은 작업을 DBMS에 요청하고, DBMS가 데이터베이스를 다뤄 결과를 돌려준다.

| 파일 시스템의 문제 | DBMS |
|---|---|
| 데이터 중복 | 하나의 소프트웨어가 관리하므로 중복을 피한다 |
| 응용 프로그램이 각자 데이터를 직접 관리 | 여러 프로그램이 하나의 DBMS를 통해 **동시에 공유** |
| 프로그램마다 데이터 쓰는 방식이 다름 | 관리 방식이 **통합**된다 |
| 데이터가 특정 프로그램에 종속 | 프로그램을 바꿔도 데이터는 그대로 쓸 수 있다 |

실무에서는 데이터베이스와 DBMS를 굳이 구분하지 않고 그냥 DB라고 부른다.

## 데이터 모델 네 가지

데이터를 저장하는 방식을 정의한 개념 모형이다.

### 계층형

트리 구조. 부모-자식 관계로 **일대다(1:N)** 를 표현한다. 하나의 부모가 여러 자식을 가질 수 있지만, **자식은 부모를 하나만 가진다.** 1960년대 말~1980년대 말에 많이 썼다.

### 네트워크형

그래프 구조. 계층형의 제약을 풀어 **자식이 여러 부모를 가질 수 있다.** 망형 데이터 모델이라고도 한다.

### 객체 지향형

1980년대 후반 등장. 데이터를 독립된 객체로 다루고 상속·오버라이드를 쓸 수 있다. 그런데 **상용 DBMS는 많지 않다.** 이유가 몇 가지 있다.

- 관계형이 이미 성숙했고 기업들이 채택하고 있었다. 전환 비용과 위험이 컸다
- 객체 지향 DB끼리 일관된 표준이 없었다
- 초기 성능이 관계형보다 떨어졌다
- 관계형이 더 직관적이고 단순했다
- **ORM이 등장하면서** 객체 지향 언어를 쓰면서도 관계형 DB의 장점을 누릴 수 있게 됐다

오라클처럼 관계형에 객체 개념을 얹은 **객체 관계형(object-relational)** 으로 영역을 넓힌 제품들은 있다.

### 관계형

1970년 에드거 프랭크 커드가 제안했다. 다른 모델과 달리 **데이터 간의 관계(relationship)** 에 초점을 둔다.

사원과 부서 정보를 한 덩어리로 관리하면 구조는 단순하지만 중복이 생긴다.

| 사원 번호 | 이름 | 직급 | 부서 이름 | 위치 |
|---|---|---|---|---|
| 0001 | 홍길동 | 과장 | **회계** | **서울** |
| 0002 | 성춘향 | 대리 | 연구 | 인천 |
| 0004 | 심청이 | 사원 | **회계** | **서울** |

회계팀 이름이 바뀌면 해당 부서 사원을 전부 찾아 고쳐야 한다. 그래서 **중복될 수 있는 데이터는 별도 릴레이션으로 떼어내고 코드로 연결한다.**

| 사원 번호 | 이름 | 직급 | 부서 코드 |
|---|---|---|---|
| 0001 | 홍길동 | 과장 | 10 |
| 0002 | 성춘향 | 대리 | 20 |

| 부서 코드 | 부서 이름 | 위치 |
|---|---|---|
| 10 | 회계 | 서울 |
| 20 | 연구 | 인천 |

### 구성 요소 세 가지

| 개념 | 관계형 DB에서 |
|---|---|
| **개체(entity)** | 테이블 (릴레이션) |
| **속성(attribute)** | 열(column). 데이터의 가장 작은 논리적 단위 |
| **관계(relationship)** | 외래키(foreign key) 등으로 구현 |

이 셋 위에서 **독립성**과 **무결성** 같은 개념이 정의된다.

## SQL 다섯 갈래

SQL은 Structured Query Language의 약자로, RDBMS에서 데이터를 다루는 질의 언어다.

| 종류 | 무엇을 다루나 | 명령 |
|---|---|---|
| **DQL** Data Query Language | 저장된 데이터를 **조회** | `SELECT` |
| **DML** Data Manipulation Language | 테이블의 **데이터** | `SELECT` `INSERT` `UPDATE` `DELETE` |
| **DDL** Data Definition Language | 테이블·인덱스 등 **객체** | `CREATE` `ALTER` `DROP` `TRUNCATE` |
| **TCL** Transaction Control Language | **트랜잭션** | `COMMIT` `ROLLBACK` |
| **DCL** Data Control Language | 사용 **권한** | `GRANT` `REVOKE` |

`TRUNCATE`가 DDL인 게 헷갈리기 쉽다. 내부적으로 DROP 후 CREATE에 가깝게 동작하므로 **롤백이 안 된다.** `DELETE`(DML)와 여기서 갈린다.
