## 셋의 관계부터

이름이 비슷해서 한 가족처럼 보이지만 계보가 다르다.

- **FTP** — 파일 전송 프로토콜의 원조. 평문 통신이라 지금은 실무에서 잘 쓰지 않는다
- **FTPS** — FTP에 TLS/SSL 암호화를 입힌 것. HTTPS가 HTTP에 한 것과 같은 방식
- **SFTP** — FTP와 무관하게 **SSH 위에서 처음부터 새로 설계된** 파일 전송 프로토콜

SFTP를 "Secure FTP"로 풀어 FTP의 보안판이라고 이해하면 틀린다. IETF SECSH 워킹 그룹이 SSH 확장으로 따로 만든 프로토콜이고, FTP와는 명령 체계 자체가 다르다.

## FTP (21번 포트) — 채널이 두 개라는 게 함정

FTP는 **명령 채널(21번)과 데이터 채널(20번 또는 임의 포트)을 분리**해서 쓴다. 이 구조 때문에 방화벽·NAT 환경에서 문제가 생기고, 그걸 풀기 위한 두 가지 모드가 있다.

| | 연결 방향 | 흐름 |
|---|---|---|
| **액티브 모드** | 데이터 채널을 **서버가** 클라이언트 쪽으로 연다 | 클라이언트: "내 포트로 연결해" → 서버가 접속 |
| **패시브 모드** | 데이터 채널을 **클라이언트가** 서버 쪽으로 연다 | 서버: "이 포트 열어뒀어" → 클라이언트가 접속 |

클라이언트가 방화벽·NAT 뒤에 있으면 서버가 클라이언트로 들어오는 연결이 막히므로 **패시브 모드**를 쓴다. FTP 연결이 목록 조회에서 멈춘다면 대부분 이 모드 문제다.

## FTPS (990번 포트) — FTP + TLS

FTP의 두 채널을 TLS/SSL로 암호화한 것이다. 공개키 방식으로 세션 키를 교환하고, X.509 인증서로 서버를 인증한다.

- 장점 — FTP 인프라를 그대로 쓸 수 있고, 인증서 기반 인증이 강력하다
- 단점 — **데이터 채널이 여전히 별도라 방화벽 설정이 복잡하다.** 디렉터리 목록 형식, 파일명 인코딩에 표준이 없어 클라이언트마다 동작이 다를 수 있다

## SFTP (22번 포트) — SSH의 파일 전송판

SSH 연결 하나 위에서 모든 것을 처리한다. 채널이 하나라 방화벽에 열 포트도 22번 하나다.

- 장점 — **단일 연결**, 균일한 디렉터리 목록 형식, 파일 잠금·권한 조작 같은 부가 기능
- 단점 — 이진 프로토콜이라 사람이 읽을 수 없고, SSH 키 관리가 인증서보다 번거로울 수 있다

| | FTPS | SFTP |
|---|---|---|
| 기반 | FTP + TLS/SSL | SSH |
| 채널 | 명령/데이터 2개 | **1개** |
| 방화벽 | 데이터 포트 범위를 열어야 함 | 22번 하나 |
| 인증 | X.509 인증서 | SSH 키 / 비밀번호 |

## 무엇을 쓰나

새로 구성한다면 **SFTP가 먼저다.** 포트 하나로 끝나 방화벽 협의가 간단하고, 서버에 OpenSSH만 있으면 된다. FTPS는 기존 FTP 인프라와 인증서 체계를 이미 갖춘 조직에서 의미가 있다. 평문 FTP는 내부 폐쇄망의 레거시 연동이 아니라면 쓰지 않는다.

같은 계보로 **텔넷(23번) → SSH(22번)**의 관계가 있다. 평문 원격 접속인 텔넷을 SSH가 대체했고, FTP 자리를 SFTP가 대체한 셈이다.
