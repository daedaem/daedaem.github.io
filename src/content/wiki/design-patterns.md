## 디자인 패턴이란

**소프트웨어 설계에서 반복되는 문제에 대한 표준적인 해법과 그것을 부르는 이름**이다. GoF(Gang of Four)라 불리는 네 명이 처음 구체화했다.

이름이 있다는 게 생각보다 중요하다. "여기에 팩토리를 두자"라고 말하면 설명이 끝난다.

## 세 가지 분류

| 분류 | 무엇을 다루나 | 예 |
|---|---|---|
| **생성** | 객체 인스턴스를 만드는 방법 | 팩토리 메서드, 싱글톤 |
| **구조** | 클래스와 객체를 조합해 더 큰 구조를 만드는 방법 | 프록시 |
| **행동** | 객체들이 상호작용하고 역할을 나누는 방법 | 옵저버, 전략 |

## 싱글톤 패턴

하나의 클래스에 **인스턴스가 오직 하나만** 존재하게 한다. 객체를 만들 때마다 메모리를 할당받으므로, 한 번 만든 걸 재활용해 낭비를 막는다.

주로 **여러 곳에서 공통으로 써야 하는 것**에 쓴다 — DB 연결 모듈, 스레드 풀, 캐시, 로그 기록 객체.

구현 방식은 여럿이다. Lazy Initialization(초기화 지연), 거기에 Double-checked Locking을 더한 것, Holder에 의한 초기화 등.

### 싱글톤의 문제

**테스트가 어렵다.** 단위 테스트는 서로 독립적이어야 하는데, 싱글톤은 **미리 만들어진 하나의 인스턴스를 공유**한다. 테스트마다 독립적인 상태를 만들기가 어렵다.

**모듈 간 결합이 강해진다.** 쓰는 쪽이 구체적인 클래스를 직접 부르게 되기 때문이다.

### 의존성 주입(DI)이 푸는 것

메인 모듈이 하위 모듈을 직접 만들지 않고, **중간에 주입자를 둔다.**

- 모듈을 쉽게 교체할 수 있어 **테스트가 쉬워진다**
- 의존성 방향이 일관되어 관계가 명확해진다

원칙은 하나다.

> 상위 모듈은 하위 모듈에서 아무것도 가져오지 않는다. **둘 다 추상화에 의존하고, 추상화는 세부 사항에 의존하지 않는다.**

공짜는 아니다. 클래스 수가 늘어 복잡성이 올라가고, 약간의 런타임 비용이 붙는다.

## 팩토리 메서드 패턴

**객체를 사용하는 코드에서 생성 부분을 떼어내 추상화한다.** 상위 클래스가 뼈대를 정하고, 하위 클래스가 실제로 무엇을 만들지 결정한다.

핵심은 **쓰는 쪽이 무엇이 만들어지는지 몰라도 된다**는 것이다. 조건에 따라 다른 객체를 돌려주는 분기가 한곳에 모인다.

## 전략 패턴

정책 패턴이라고도 한다. **어떤 동작을 하는 로직들을 각각 캡슐화해두고, 컨텍스트 안에서 갈아 끼운다.**

객체의 행위를 바꾸고 싶을 때 그 객체를 고치지 않는다. 전략을 바꾼다. 인증 라이브러리(passport 등)가 전형적인 예다 — 로컬 로그인, OAuth, JWT가 각각 하나의 전략이다.

## 옵저버 패턴

**상태를 가진 주체**와 **그 변화를 알아야 하는 관찰자**가 있다. 주체의 상태가 바뀌면 등록된 옵저버들에게 알린다. 1:N 관계다.

MVC 패턴이 이걸 쓰고, Vue의 `ref`·`reactive`도 프록시 객체로 옵저버 패턴을 구현한 것이다.

## 프록시 패턴

**대상 객체에 접근하기 전에 그 흐름을 가로채 앞단 인터페이스 역할**을 한다.

서버 앞에 두어 캐싱·로깅에 쓰는 프록시 서버가 대표적이다(nginx). 클라이언트는 프록시를 통해 간접적으로 서비스에 접근한다.

## MVC · MVP · MVVM

| | 세 번째 요소 | 뷰와의 관계 |
|---|---|---|
| **MVC** | Controller | 1:N |
| **MVP** | Presenter | **1:1** — 더 강하게 결합 |
| **MVVM** | ViewModel | 1:N. VM이 뷰를 추상화 |

**MVC**의 컨트롤러는 모델과 뷰를 잇고 생명주기를 관리한다. 셋으로 나뉘어 각각에 집중할 수 있고 재사용·확장이 쉽지만, **애플리케이션이 복잡해질수록 모델과 뷰의 관계가 얽힌다.**

**MVVM**은 그 C를 ViewModel로 바꾼 것이다. Vue.js가 대표적이다.

## Flux 패턴

**단방향 데이터 흐름**으로 상태를 예측 가능하게 관리하는 클라이언트 아키텍처다. 데이터가 한 방향으로만 흐르므로 어디서 상태가 바뀌었는지 추적하기 쉽고 유닛 테스트가 쉽다. 대신 학습 곡선이 가파르고 문법이 장황하다.
