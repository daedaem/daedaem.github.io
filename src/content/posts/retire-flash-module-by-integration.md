> 회사·시스템명, 연동한 외부 서비스의 이름, 실제 연동 구성과 비용 수치는 공개하지 않는다.

업무 시스템에 계약 기능을 맡던 Flash 기반 모듈이 남아 있었다. Flash 지원 종료와 브라우저 호환성 문제로 파트너사의 설치·접속 문의에 전화로 대응하는 일이 반복됐다. 기능을 계속 쓰기 위한 안내가 운영 업무의 부담이었지만, 계약 기능 전체를 고도화하는 작업은 진행되지 못하고 있었다.

계약 작성 기능을 제공하는 외부 서비스와 연동해 대체하기로 했고, 그 구현을 맡았다. 기존 모듈을 중단하고 계약 작성만 외부 서비스의 API를 활용해 처리하되, 그 앞뒤의 업무 처리와 결재 상태 흐름은 담당 시스템 안에 새로 만드는 작업이었다.

## API를 붙이는 것 외에 새로 만든 부분

외부 서비스의 API를 호출하도록 바꾸는 것만으로 끝나는 일은 아니었다. 계약 요청 전후의 업무 처리와 상태 반영 로직이 옛 모듈에 맞춰져 있었다.

여러 계층에 흩어진 기존 연동 로직을 제거하고, 외부 서비스 연동에 맞는 전후 업무 로직을 새로 개발했다. 이 글의 API는 외부 서비스가 제공하는 연동 수단을 뜻한다. 상대 서비스의 API 자체를 새로 개발했다는 의미는 아니다.

수행 범위는 다음과 같다.

- 외부 서비스 API 연결과 계약 작성 요청 전후 처리 개발
- 계약 진행 상태를 담당 시스템에 반영하는 동기화 배치
- 적재 실패 건을 초기 상태로 되돌리는 복구 처리
- 연동에서 받을 수 있는 상태에 맞춘 결재 상태 흐름 개발

## 상태 동기화와 적재 실패 복구

전환 뒤에는 외부 서비스에도 데이터를 적재하는 흐름이 됐다. 계약 진행 상태는 배치가 주기적으로 담당 시스템에 반영하도록 구성했다.

적재에 실패한 건은 초기 상태로 되돌리도록 설계했다. 요청이 정상 처리되지 않았는데 진행 중인 것처럼 남으면 사용자가 다음 조치를 하기 어렵기 때문이다.

계약 작성 버튼은 기존 결재 상태에 연동되어 있었다. 상태가 초기 상태로 돌아가면 버튼이 다시 활성화되어 사용자가 재진입할 수 있었다. 별도의 실패 알림 화면을 새로 만든 것으로 설명하지 않는다.

이 흐름은 실패 건을 되돌리는 처리다. 사용자가 다시 요청할 수 있다는 것과 자동 재시도·중복 방지를 구현했다는 것은 다른 이야기이며, 후자의 구현 성과를 주장하지 않는다.

## 상태 구분이 달라 화면과 업무 흐름도 정리했다

기존 시스템은 계약 진행 상태를 세분화하고, 상태별로 여러 화면에서 업무를 처리하는 구조였다. 같은 시스템 안에서 데이터를 직접 조회할 수 있어 각 단계의 상태를 바로 확인할 수 있었다.

외부 서비스와 연동한 뒤에는 조건이 달라졌다. 새 API가 제공하지 않는 값도 있었고, 시스템 사이에서 상태를 전달하고 반영하는 데 시간 차이도 생겼다. 기존 화면에서 나누던 세부 상태를 연동 대상의 상태 정보와 그대로 일대일로 대응시킬 수 없었다. 예전 구분을 그대로 남겨 두면 그 화면에서 보여 줄 상태를 연동 정보만으로는 판단하기 어려웠다.

기존 코드를 분석하고 운영하며 파악한 업무 흐름을 바탕으로, 각 상태가 쓰이는 화면과 처리 조건을 확인했다. 실제 업무는 비슷하지만 용어나 상태 구분이 달랐던 단계는 현업과 회의하며 통합하고, 계속 필요한 업무 구분을 정리했다. 그 기준을 화면 표시와 처리 로직에 반영했다.

판단 기준은 **연동으로 확인할 수 있는 정보 안에서 실제 업무에 필요한 구분을 남기는 것**이었다. API가 주지 않는 세부 단계를 임의로 추정해 채우지 않고, 현업이 사용할 화면과 업무 흐름을 함께 맞췄다.

## 결과

외부 서비스 연동과 전후 업무 로직 개발로 Flash 기반 계약 모듈을 대체하고, 기존 환경의 유지보수 계약을 해지할 수 있게 됐다. 비용 수치는 이 글에 공개하지 않는다.

재사용한 것은 외부 서비스의 계약 작성 기능과 API다. 새로 개발한 것은 그것을 담당 시스템의 업무에 연결하는 전후 처리, 결재 상태 흐름, 상태 동기화와 실패 복구다. 두 범위를 구분하는 것이 이 작업을 설명하는 핵심이다.

관련 기록으로는 전환 검증 중 발견한 [금액의 정수 오버플로](/posts/integer-overflow-negative-amount/)가 있다. DB 값과 VO의 값을 대조하고, VO의 금액 필드를 int에서 long으로 변경해 정상화한 과정을 적었다.

**정정(2026-09-30):** 연동 대상을 '기존 계약 시스템'으로 잘못 적었던 것을 바로잡았다. 기존 모듈을 중단하고 계약 작성만 외부 서비스에 API로 연결했으며, 결재 상태 흐름을 새로 만든 범위를 본문에 반영했다.

**보충(2026-10-06):** 당시 운영 부담과 상태 체계 차이를 구체화하고, 현업과 협의해 단계·화면·처리 기준을 정리한 과정을 추가했다. 실제 내부 상태명과 연동 구성은 생략했다.
